# vivo 取件个人模板验收

## 首次试运行的真机观察

在内测版新建模板，从「官方待取列表」或「取件亮码」示例点击「理解需求并匹配模板」后，在电脑运行：

```powershell
.\tools\wait-carddock-trial.ps1 -Serial <设备序列号>
```

beta.10 起，这条命令通过 Android 的 Activity dump 读取卡坞自己的试运行阶段、预览是否生成和页面读取是否已连接。等待 `SUCCEEDED preview=true` 后再检查卡面的按钮与来源。试运行期间使用系统自带的 `uiautomator dump` 会影响无障碍服务，本机实测曾导致解绑；验收改用上述命令。测试者也可以直接在手机上看预览。

列表试查会短暂进入官方列表并回到卡坞。亮码试查核对官方身份码页的标题和刷新提示；在预览主动点击「出示取件码」才把该页交给用户。两种试查都只在卡坞仍在前台且服务短暂重绑时从新的查询屏重试一次。遇到菜鸟欢迎页占据主屏时，用系统返回键退出该页，回到卡坞后再试运行。

## 正常入口

在卡坞「模板 → 新建模板」输入“帮我查待取快递，到驿站时一键出示身份码”。Mika 在菜鸟首页寻找实际可见的入口；若同页有多个候选，用户在卡坞选择一个示范。个人模板必须独立重放亮码路径两次，并取得包裹查询预览才能发布。在「空间＋」选模板，试运行并添加到空间。点卡片主体刷新待取状态；点「出示身份码」才打开官方应用。

## 设备和范围

2026-11-20，vivo V2359A。用户在菜鸟亲自完成身份码授权。首页「出库码」到达官方「身份码」页，页面有刷新提示。「取包裹」页明确显示“暂无待取包裹”。淘宝首页可进入「菜鸟驿站」，当次未核实身份码页，明确要求淘宝的需求保留为草稿。菜鸟内部身份码 Activity 未导出；卡坞使用对外开放的首页，再由页面服务触发已验证的可见入口。码图、码值和授权条款不进入模板或模型。真机附件仅展示卡坞页面。

本版按用户确认，通过系统最近任务回到原卡。来源的系统返回键先回菜鸟首页。取件卡只保存待取状态和入口种类；出示身份码单独执行，查询时间只由成功查询更新。明确有件的文字只作为状态依据，不把某一个驿站的件数计为全部件数。有件样本和现场取件扫码仍需另验。

## 复现与回归

- 早期版本走普通启动器，后台可能停在启动广告页；改从公开首页开始。实测试查中的身份码页由后台控件导航打开。
- 出示后普通刷新一度复用了菜鸟主屏任务，失败时保留了旧快照；将后台查询首页的任务与主屏分开。
- 查询与亮码各自拥有按钮与状态。广场当前协议仅能传递查询能力，组合模板仅在个人模板库使用，避免上传后丢失动作。

## 从需求到取件卡的最终真机记录

| 步骤 | vivo 观察 |
| --- | --- |
| 个人模板 | 从模板入口输入需求，保存后编辑并重新试查，第二版取得后台官方亮码页和待取页的证据。21/21 次主屏采样均为卡坞。 |
| 空间建卡 | 从「空间＋」选保存的模板，独立试运行并预览，14/14 次采样均为卡坞。点添加，空间出现「快递取件」卡片及「出示身份码」按钮。 |
| 冷启动和亮码 | 在后台终止卡坞进程后重开，原卡与按钮仍在。点按钮经菜鸟首页打开官方身份码页。打开系统最近任务，选择卡坞，回到同一张卡。亮码未改写核验时间。 |
| 普通刷新与断线重试 | 进程退出也会断开调试版 Mika。点卡时提示重新连接，保留上次成功快照。按「我的 → Mika 后台助手」的 USB 方法重新连接，点同一张卡显示「暂无待取包裹」，核验时间从 15:10:25 更新到 15:15:57。13/13 次采样均为卡坞。 |
| 旧卡回归与恢复 | 在原空间副本点一张原有待取卡，12/12 次主屏采样均为卡坞，刷新成功、时间更新。恢复原 12 张卡并逐字节比对一致，个人模板库保留新模板。 |

设备测试只对卡坞的查询阶段采样前台。用户主动亮码时，前台切换到菜鸟。系统强制停止该调试包还会使本机页面读取服务被关闭；验收后已在系统设置恢复。普通从最近任务返回无需重新连接助手。
