# CardDock 主应用三源交付与真机验收

2026-11-14 的 dev 交付使用根工程 `app → core`。Debug 包名为 `com.life0423.carddock.prototype`。应用使用 RuleSpec v1，卡片与选购记录分别存入应用私有目录。Mika 实验工程保留在 `experiments/mika-android`，可作为适配器参考。

## 真机复验

验收设备为 vivo V2359A，第三方 App 版本为菜鸟 8.11.1105、美团 12.69.202、京东 16.1.50。通过「我的 → 打开无障碍设置」启用「卡坞 · 页面只读核验」。若系统显示无法运行，先检查服务是否已绑定，再从系统设置重新启用。

| 功能 | 入口与复验步骤 | 已验结果 |
| --- | --- | --- |
| 菜鸟空状态 | 模板 → 菜鸟待取 · 真机。试运行或刷新后，20 秒内切换至「取包裹」页 | 核验「暂无待取包裹」，建卡、刷新、重开恢复通过 |
| 美团历史订单 | 模板 → 美团历史订单。用已授权的订单号码，25 秒内切到对应已完成订单并展开「订单信息」 | 状态和下单时间可核验。折叠或错对象时旧结果保留 |
| 京东公开身份 | 模板 → 京东商品 A 或 B | 建卡、刷新通过，核验主体 SKU、规格和商品名称 |
| 顺序核验 | 空间 → 顺序核验。菜鸟、美团逐项确认开始，京东自动执行 | 美团折叠超时后，京东 A、B 仍依次成功 |
| 京东 App 展示价 | 空间 → 京东卡 → 核验 App 展示价。60 秒内切到匹配详情，打开分享，停一秒后复制链接，详情恢复后切回卡坞 | 两款均采价成功。普通刷新保留原价格与采价时间。错商品、旧剪贴板、浮窗和取消均拒绝写入 |
| 京东选购 | 选购 → 保存选购任务。重开后检查快照和备注，再采价 | 重开恢复通过。A 原条件下显示「未变化」，B 价签和优惠条件变化后显示「无法核验」 |
| 菜鸟模型候选 | 我的 → 模型设置，模板 → 用模型生成菜鸟候选。生成、试运行、确认保存依次执行 | DeepSeek Flash 真实生成、试运行和保存通过。普通刷新客户端模型请求增量为 0。清除配置后原卡仍可刷新 |
| 菜鸟规则替换与回退 | 空间 → 菜鸟卡更多菜单。选择替换或回退，打开取包裹页完成试运行后确认 | 原卡 ID、名称和位置保留。超时后原规则和快照保留。回退后普通刷新通过 |

菜鸟内置规则、菜鸟模型规则、美团 O1、京东 A、京东 B 各记录了 10 次独立成功刷新。另记录了切页超时和取消。vivo 曾出现触摸分发超时，本版将菜鸟和美团页面查询放到后台线程，后续实测通过，系统超时根因仍待确认。

## 开发入口

- `app/src/main/kotlin/com/life0423/carddock/platform` 承接真机页面采样和京东公开商品页核验。`core` 保留 RuleSpec、试运行、顺序核验和卡片提交逻辑。
- 京东 A 固定 SKU `100305104289`，B 固定 SKU `100312915069`。展示价要求分享前后详情一致、本次复制的链接与公开页均匹配目标 SKU。B 当前已知的短规格别名仅按完整别名匹配。
- 模型配置支持 OpenAI 兼容的 HTTPS 基础地址，客户端追加 `/chat/completions`。模型仅收到固定脱敏需求。配置使用 Android Keystore 加密，队友需在自己的设备重新配置服务。
- 替换使用已保存的同类菜鸟候选或内置规则，回退使用当前卡自己的上一版。确认时将规则、上一版与本次快照原子提交。
- 复验使用授权账号。订单号、模型密钥、原始第三方页面和设备私有文件留在本机。
- 取件码、实时配送、自动跳转和模板导入导出仍在后续范围。

## 构建与测试

JDK 17、Android SDK Platform 35。在仓库根目录执行：

```bash
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

本版 Windows 实测 core 51 项、三源相关 app 11 项通过，Lint 0 错误和 19 条警告，Debug 构建成功。此前同机全量 app 测试的 6 项失败也在 main 基线复现，涉及 Robolectric 原子文件存储及启动后刷新超时。验收 APK 从 `app/build/outputs/apk/debug/app-debug.apk` 获取。
