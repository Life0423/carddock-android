# 票夹流程与应用内展示验收

2026-11-21，vivo，根工程 `app → core`。本轮覆盖安装保留用户空间，并在同机独立数据目录验收新增卡与广场发布。

## 三个入口

| 入口 | 用户操作 | 保存或发布的内容 |
| --- | --- | --- |
| 模板库 → 新建 | 写需求，可填写名称；开始试运行。多义需求沿用一次示范。核对来源、字段和时间；可点字段切换票面重点。 | 保存可复跑的模板定义及字段布局。草稿允许稍后继续。核验未通过时无法保存为可用模板。 |
| 空间＋ → 选模板 | 可从选择器跳去新建模板，配置时也可更换模板。填写卡片名称，按需给特定历史订单指定目标。试查后添加。 | 建卡时读取本机新结果，保存模板版本、选定布局与首次成功快照。后续刷新复用布局。 |
| 广场 → 发布 | 复用「我的」账号。选择可公开的已核验模板，查看名称、版本、作者、说明与字段，然后确认发布。 | 服务确认后显示成功。自定义字段顺序随支持的公开能力传递；依赖个人导航或亮码动作的模板仍在个人库中。 |

## 本轮真机记录

- 正常安装包从菜鸟待取模板读到明确的“暂无待取包裹”与成功核验时间。从配置选择「更换」可重新选模板；原空间 12 张已满时给出容量提示。
- 同机隔离包使用相同业务代码，独立包名、私有数据和回环广场地址。选京东商品 A 做真实试运行，将首字段从规格换为商品名称，核验时间保持原值。保存模板，再从空间选择该模板试查并添加。再次点卡成功，核验时间更新，持久化顺序为商品名称、规格、SKU。
- 从 vivo 发布入口注册临时账号后回到上传选择页。服务返回成功，第二个账号通过 API 下载，得到同样的字段顺序且下载量变为 1。测试数据仅进入本地隔离服务。
- 组合取件卡第一次从需求查找亮码入口超时，卡坞占主屏 42/42 次采样。稍后从个人库选择已保存的组合模板独立试运行成功，菜鸟使用副屏 361、362，卡坞占主屏 27/27 次采样。结果显示待取状态、成功核验时间与「出示取件码」。
- 从原空间主动亮码，前台切到菜鸟。本机核对到官方身份码页标题与刷新提示，随后返回卡坞。验收只记录了状态，没有记录凭证。实际驿站扫码仍待官方联调。
- 独立测试 Activity 使用自有 Presentation 在副屏 360 生成两次纯色变化，物理主屏 0 上的宿主 SurfaceView 连续收到两次匹配像素。此实验验证实时 Surface 通道，未在宿主显示第三方身份码。
- 核心单测 61/61，Compose 界面回归 8/8，广场服务测试 2/2。Android lint 零错误，48 条警告。

- 最终版本再次从新建模板输入同一取件需求。自动学习、独立重跑及读取待取状态后得到“模板卡面预览”“暂无待取包裹”和“出示取件码”。主屏 23/23 次采样均为卡坞。首次入口超时仍记录为偶发现象。
- 收尾时 vivo 停在卡片空间。原 12 张卡及 6 份个人模板对应文件与覆盖安装前 SHA-256 完全相同。两个隔离验收包均已移除，测试服务和端口映射已关闭。常用 APK 与手机安装包 SHA-256 均为 `8f8c4375d82bc03da3dfe6d3508a854b0d58b6050739d692bf0abc6e5e94d9ac`。

## 应用内展示的产品边界和执行顺序

1. **普通查询结果**。使用已核验字段生成原生票面。数量卡突出数量，提醒默认突出通知时间，用户选定字段后预览和空间沿用该顺序。增加新的结果类型时，先确定字段角色、单位和空态，再挑选对应图标、主副字段与颜色。验证改名、重排、刷新失败保留旧值以及较大系统字号。
2. **官方身份码**。向菜鸟／淘宝确认面向消费者的授权展示能力、应用包名与签名要求、沙箱、用户授权、码有效期、退出与撤销回调。取得开放资格后，优先承载官方 SDK 的 View 或合作方明确允许的 Activity。用测试账号验证到期更新、切到后台、断网、撤销，以及站点测试扫码。通过前仍通过卡片按钮打开官方页。
3. **实时官方页面**。仅在提供方允许宿主展示该页面时开展互操作测试。先用合作方的非凭证测试页核对两次画面变化、主窗口保持、旋转和关闭后释放；随后按合作方流程验证凭证可用性。Android 跨应用 Activity 嵌入需要来源声明支持，受保护窗口在普通虚拟显示器上会留白。当前 Mika 真机链路依赖 Android 14+ 和调试助手，普通安装渠道另需验证。任一条件不足，卡片直接打开官方页，并保留原卡结果和核验时间。

已核对的公开 API 分别供小件员验证取件码、用身份码获取实名信息。尚未确认卡坞可用的消费者动态亮码组件。参见[淘宝开放平台取件码验证](https://developer.alibaba.com/docs/api.htm?apiId=29149)、[阿里开放平台身份码接口](https://jaq-doc.alibaba.com/docs/api.htm?apiId=32020)、[Android 官方跨应用嵌入说明](https://developer.android.com/develop/ui/views/layout/activity-embedding)和[安全虚拟屏说明](https://developer.android.com/reference/android/hardware/display/DisplayManager#VIRTUAL_DISPLAY_FLAG_SECURE)。

## 卡内详情 · 11 月 21 日

点首页卡面刷新，打开“更多 → 查看详情”只展示该卡的已核验快照，沿用首页主字段和票纸。来源订单的下单时间与“卡坞上次成功核验”分别标明。金额卡实读订单合计 ¥31.50（CNY），下单于 10 月 29 日，卡坞 11 月 21 日再次核验；组合取件卡显示“暂无待取包裹”。在详情点“出示取件码”打开菜鸟官方身份码页，返回时成功快照保持相同。两张卡均验了 Mika 断连和 1.6 倍系统字号。实际界面、测试口径和完整时间见 artifacts/carddock-main/2026-11-21-card-details/验收记录.md。

## 允许嵌入的普通页面 · 11 月 21 日

在 vivo V2359A 的卡坞隔离版中，从取件卡进入自建营业看板。提供方可见授权页确认后，在单独应用进程的私有虚拟屏绘制，宿主接收实时帧和局部触摸。已用不同签名的两个测试包验证双方证书校验、取消、横竖屏切换、实时数字变化、关闭释放和来源断连返回原卡。首轮直接冷绑定未连上；通过的路径含提供方可见授权。正式版继续通过“出示取件码”打开官方页。菜鸟公开了按运单和手机号查询的单包裹取件码服务；消费者动态身份码组件的开放资格仍待提供方确认。证据与来源位于 artifacts/carddock-main/2026-11-21-embedded-page。
