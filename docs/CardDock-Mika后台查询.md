# CardDock 内置 Mika 后台查询

根工程继续使用 `app → core`、现有包名及卡片数据。CardDock APK 内包含从 Mika 移植的显示屏与 Binder 交接代码。调试时由 ADB 从同一 APK 启动 shell 执行进程，用户只安装和打开卡坞。助手只接受该安装的应用 UID，接口只允许创建菜鸟、美团查询屏和释放助手自有屏。

Mika 上游来源为仓库内 `experiments/mika-android`。可信屏标志、shell 系统上下文、主屏任务检查和 Binder 交接分别参考 `ShellService`、`ShellContext`、`HelperProcess`。包内附有 Mika 的 LICENSE 和 NOTICE，`ShellContext` 保留原 scrcpy 归属。

## vivo 调试复测

1. Android 14 以上设备覆盖安装根工程 Debug APK，在系统中开启「卡坞 · 页面核验」。覆盖更新后若显示未连接，在系统设置关闭再开启。
2. 连接已授权的 USB，在仓库根目录执行 `./tools/start-mika-helper.ps1 -Serial <设备序列号>`。到「我的」核对页面核验与 Mika 后台助手均已连接。卡坞进程退出或设备重启后重新运行命令。安装包内的无线配对和自动恢复仍待开发。
3. 在空间直接点菜鸟卡。后台经菜鸟公开首页入口进入「取包裹」，只确认明确的待取空状态。主屏留在卡坞，核验通过后结果与时间原位更新。
4. 美团旧卡先在「详情 → 设置后台订单路由」填入同笔授权订单的 19 位路由号。点卡后后台打开该订单并展开订单信息。号码与下单时间必须来自同一已完成订单。路由和订单号码只留在本机卡片数据中。清除路由可恢复旧版手动核验。
5. 核验时用 Activity 按显示屏查看主屏与目标 App。等待运行结束再使用 UIAutomator，避免它暂停卡坞的无障碍服务。通过后核对卡片的有效结果、成功时间和运行状态。超时、取消或身份不匹配保留上次有效结果。京东 App 自动采价独立验收。

## 失败复现和修正

- 菜鸟从桌面启动组件打开时，欢迎页广告曾另起主屏任务，触发停止核验。直接启动取包裹组件又被系统拒绝，因为该组件不对外开放。现在从可外部打开的首页组件进入虚拟屏，在唯一的「取包裹」入口上执行点击。
- 美团使用真实的本机授权路由开放详情后，较矮的虚拟屏未同时显示订单号和下单时间。扩大虚拟屏后捕获到完整字段，并确认这套布局将完成状态放在同一个详情列表的独立状态区。解析限定该状态区及同一个订单信息分组。所见对象仍由规则引擎与授权订单号码核对。

## 2026-11-17 验收结果

vivo Android 16 最终 Debug APK 正常样本为菜鸟 10/10、美团 O1 10/10，各含五次强停后冷启动及五次未强停查询。每次主屏 Activity 采样均为卡坞，结果和核验时间原位更新，结束后没有遗留助手显示屏。菜鸟耗时 1.33–3.26 秒，美团 1.44–3.44 秒。停止助手后点菜鸟提示未连接并保留原时间，经 USB 恢复助手后查询成功。验证仅覆盖该设备和已授权对象。
