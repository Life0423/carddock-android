# vivo 外卖月账本阶段验收

## 卡坞入口与验收标准

从「模板 → 新建模板」输入上述需求，点「生成候选」。默认只读取可见文字和控件结构。来源无法通过控件状态证明筛选时，页面提供单次本机比对选项。每次试查从指定来源的启动入口进入后台屏，只把可选导航名称交给模型。模板重跑固定同一截止时刻，刷新重新取截止时刻。

订单按稳定订单号跨页去重。相邻页面要有有序重叠，逐单核对订单类型、状态、下单时间和金额。只有明确标为原实付的字段能单独提供金额。账单路径需要支付成功扣款与原单人民币合计相符，而且「查看原订单」回到同一订单号和同一秒的下单时间。重名、金额冲突、页面范围不明、找不到末尾或无法核对总笔数及行号，都应保留上轮成功结果，停止当次发布。

来源的筛选结果与旧订单列表在控件树中同时存在。真机有页面只完整露出时间行的一部分或状态行的一部分。验收时须证明只读了当前结果层，并在第二次独立试查中得到同一逐单指纹。完成模板保存、空间建卡和刷新后，才可将月账本标记为产品入口通过。QQ 单条发送阶段仍以前述验收通过为前提。

## 2026-11-20 复测

### 从卡坞重现

在「模板 → 新建模板」输入上文需求，点「生成候选」。来源的「近3个月」用来取得覆盖整个目标月的候选范围，最终仍按下单秒数落入 [截止时刻减一个自然月，截止时刻) 计算。来源未暴露选中状态时，在卡坞点「允许本次在本机比对筛选项并重试」。下次操作重新请求授权。正常的按模板建卡和已保存卡刷新入口也能处理这项请求。失败后保留上次成功快照及其核验时间。

旧版曾在提交筛选后停在「来源未提供可核验的订单结果页」。同一页的前后对照揭示了原因。提交前只有一个订单列表；提交后，旧视口仍在，新结果和固定工具栏由同一父节点分别绘制在它上面。筛选面板的操作栏也与正文相叠。此次调整按保留的旧视口、控件分支、绘制顺序和边界辨认新列表及操作栏。月账本从来源的独立启动入口开始，账单核验要求同层的支付状态、金额与原单链接。改动沿用 app → core，无来源包名、固定路由或订单号分支。

### 复测方法

1. 区分来源 App 主屏的人工对照和卡坞入口的后台试运行。两者各自记录结果。读取后台集合时，只有能辨认结果层，以及确认重开筛选后选项仍然生效，才进入逐单核验。
2. 跨屏对账要在相邻两屏分别打开同一笔，核对稳定订单号和秒级下单时间；逐笔金额必须有可回链的原实付依据。重复看到相同记录只能证明这笔可去重。
3. 要验收月总额，还需要同一筛选范围的集合覆盖依据，以及全部纳入订单的金额。取得这些证据后，从模板入口重复试查同一截止时刻，逐笔一致再保存、空间建卡、刷新。另验失败重试是否保留上次成功时间。
